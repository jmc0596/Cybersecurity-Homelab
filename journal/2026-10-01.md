## Virtualisation Concepts Learned

The lab helped establish the relationship between the main virtualisation components.

```text
virt-manager
      │
      ▼
   libvirt
      │
      ▼
   QEMU/KVM
      │
      ▼
Kali Linux VM
```

KVM provides hardware-assisted virtualisation through the Linux kernel.

QEMU provides the virtual hardware presented to the guest.

libvirt provides management of virtual machines, networks and storage.

virt-manager provides a graphical interface for managing the libvirt environment.

## Troubleshooting

### Virtual Secure Boot

The VM initially failed to boot the Kali installer and displayed:

```text
Access Denied -- rejected probably by Secure Boot
```

The issue was investigated through the virtual UEFI firmware.

The virtual UEFI Secure Boot configuration was accessed through:

```text
Device Manager
→ Secure Boot Configuration
→ Attempt Secure Boot
```

Secure Boot was disabled for the virtual machine.

The Kali installer subsequently booted successfully.

This demonstrated that virtual firmware settings can affect the guest independently of the physical host's firmware configuration.

## Libvirt Connection Scope

An important troubleshooting lesson was that libvirt can have different connection scopes.

The default `virsh` command initially did not show the VM.

The VM was managed through:

```text
qemu:///system
```

Using:

```bash
virsh -c qemu:///system list --all
```

correctly displayed the VM.

This demonstrated the difference between the system-wide libvirt instance and a per-user libvirt session.

## Reflection

The main lesson from this lab was that virtualisation is a layered system rather than a single technology.

Understanding the relationship between QEMU, KVM, libvirt, virt-manager, virtual hardware and virtual networking will provide a foundation for the next stages of the homelab.

The troubleshooting process was also valuable because the initial boot failure was not caused by a problem with the Kali ISO or the physical computer. The problem was within the VM's virtual firmware configuration.

I also learned the importance of verifying infrastructure from both sides of a virtual environment: from inside the guest and from the host.
